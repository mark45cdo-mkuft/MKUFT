## Plain version first

A repeated shape is visible across the later MKUFT modules:

```text
an apparent single object is too coarse
→ split the decision-bearing objects or relations
→ type them separately
→ refuse automatic property transfer
→ reconnect only through a declared carrier / realisation / admissible interface
→ ask whether the repaired representation changes a fresh prediction, intervention, discriminator, recovery route, or closure decision
```

That shape is scientifically interesting, but it is **not a newly invented foundational engine**. Module 22A already states the core procedure explicitly: decompose the apparent object, type each load-bearing result, permit no untyped inheritance, test the property-carrying relation, and recurse only while the conclusion changes.

The new object here is narrower:

1. show that later modules repeatedly instantiate that already-owned operation without pretending the instances are independent confirmations;
2. subtract established neighbouring machinery before making any novelty claim;
3. define a prospective benchmark that can test whether the MKUFT implementation of this operation actually generates useful distinctions beyond strong native alternatives.

In short:

> **The knife was already in the toolbox. This module maps where it has been used and asks whether it cuts new cases better than the strongest fair alternatives.**

If it does not, the broad generator claim contracts. The valid local results do not disappear.

## 4. Prior-art subtraction — what MKUFT does not own generically

The generic ingredients have substantial established neighbours.

### 4.1 Abstract interpretation

Cousot and Cousot's abstract-interpretation programme formalises movement between concrete and abstract semantic domains, sound approximation and fixpoint reasoning. That literature removes any generic priority claim over `represent a richer object at a coarser typed level and preserve what the abstraction lawfully carries`.

Reference: Patrick Cousot and Radhia Cousot, **Abstract Interpretation: A Unified Lattice Model for Static Analysis of Programs by Construction or Approximation of Fixpoints**, POPL 1977, pp. 238–252, DOI `10.1145/512950.512973`.

### 4.2 Causal abstraction

Causal-abstraction research already formalises low-level to high-level mappings and asks whether intervention structure is preserved across abstraction.

Reference: Sander Beckers and Joseph Y. Halpern, **Abstracting Causal Models**, AAAI 2019, 33(01), 2678–2685, DOI `10.1609/aaai.v33i01.33012678`.

### 4.3 Predictive-state representations

Predictive-state representations already treat state in terms of action-conditional predictions of future observations and ask whether a representation carries sufficient predictive information for the dynamical task.

Reference: Michael L. Littman and Richard S. Sutton, **Predictive Representations of State**, Advances in Neural Information Processing Systems 14 (NIPS 2001).

### 4.4 Information bottleneck and sufficient representation

The information-bottleneck programme explicitly studies compressed representations that retain information relevant to a target variable. Minimum or task-sufficient representation is therefore not a generic MKUFT invention.

Reference: Naftali Tishby, Fernando C. Pereira and William Bialek, **The Information Bottleneck Method**, 1999/2000, arXiv `physics/0004057`.

### 4.5 Residual candidate after subtraction

## 5. Quantitative prospective generator benchmark

Module 29A already requires the parent generator to face a finite prospective portfolio test. This section supplies a compact measurable object for that requirement.

Let `\mathcal Q_{\mathrm{hold}}` be a held-out, prospectively frozen task family. For each task `q\in\mathcal Q_{\mathrm{hold}}`, let:

- `\mathcal G` denote the MKUFT generator procedure under test;
- `\mathcal B_q` be a preregistered family of strong comparator generators appropriate to that task;
- `F_q(M)` be a preregistered **higher-is-better** portfolio score for method `M` under the same declared information, time, compute, human assistance, tool access, branch/search budget, revision opportunity and stopping rule.

The score must include the complete serious attempt portfolio according to the frozen protocol. Failed branches, false positives, post-hoc repairs and search cost may not disappear merely because a successful descendant later exists.

Define the strongest native baseline for task `q` as

```math
F_{\mathrm{base}}^{*}(q)
=
\sup_{b\in\mathcal B_q}F_q(b).
```

The **prospective generator gain** is

```math
\boxed{
G_{\mathrm{gen}}(q)
=
F_q(\mathcal G)-F_{\mathrm{base}}^{*}(q).
}
```

This is the equation that matters because the sign can be negative.

Interpretation:

```text
G_gen(q) > 0
→ MKUFT generator outperformed the strongest preregistered comparator on that task under the declared scoring/resource envelope

G_gen(q) = 0 within uncertainty/tolerance
→ no demonstrated generator advantage on that task

G_gen(q) < 0
→ the strongest comparator outperformed the MKUFT generator on that task
```

No cross-task mean is permitted merely because every task has a number. If task scores are not commensurable, report the vector

```math
\mathbf G_{\mathrm{gen}}
=
\bigl(G_{\mathrm{gen}}(q_1),\ldots,G_{\mathrm{gen}}(q_m)\bigr)
```

with the preregistered portfolio rule.

If each `F_q` has been prospectively normalised to a common direction and scale and task weights `w_q` are fixed before outcome inspection, with

```math
w_q\ge0,
\qquad
\sum_{q\in\mathcal Q_{\mathrm{hold}}}w_q=1,
```

then an aggregate may be defined as

```math
\boxed{
G_{\mathrm{gen}}^{\mathrm{agg}}
=
\sum_{q\in\mathcal Q_{\mathrm{hold}}}
w_q G_{\mathrm{gen}}(q).
}
```

A finite generator-level hypothesis can then be stated as, for a preregistered material margin `\delta_{\mathrm{gen}}\ge0`,

```math
H_{\mathrm{gen}}:
\mathbb E\!\left[G_{\mathrm{gen}}^{\mathrm{agg}}\right]
>
\delta_{\mathrm{gen}},
```

with the sampling model, uncertainty interval, replication burden and decision rule specified by the concrete benchmark.

### Equation status

Under Module 29:

- the definitions above are **E1 operational scaffolds** while task family, baselines, score, budgets and stopping rules remain uninstantiated;
- they become **E2 operational statistical objects** only after those quantities are frozen prospectively and the benchmark is actually run;
- they are never promoted into a physical mechanism merely because the generator score is positive.

The subtraction is intentionally severe. A positive score against a weak straw-man baseline is not evidence of generator merit.

## 6. Required comparator family

The exact comparator family is task-specific, but a serious generator test should include the strongest applicable members of these classes:

1. **native-domain method / expert workflow** appropriate to the task;
2. **generic careful structured analysis** without MKUFT-specific machinery;
3. **matched AI-assisted research** with the same tools, data, compute, context budget and revision allowance but without the focal MKUFT procedure;
4. **matched human-assisted condition** where the human contribution is load-bearing;
5. **full-history replay / transfer control** when retained coupled history is claimed to add value, as defined in Module 24B;
6. **strong alternative representation or abstraction method** identified by the native literature;
7. another comparator whose success would materially remove the claimed MKUFT advantage.

`Strongest` is bounded by Module 24B: it means the strongest serious admissible comparator family that can change the declared inference, not an infinite catalogue of imaginable alternatives.

## 7. Relationship to human–AI superadditivity

Module 24B and this module test different parents.

Module 24B defines quantities such as

```math
G_{\mathrm{syn}}^{*}=F_{AB}-F_{\mathrm{null}}^{*}
```

and

```math
G_{\mathrm{path}}=F_{AB}-F_{\mathrm{replay}}^{*},
```

which ask whether a reciprocal Mark–Kairos or other `A\leftrightarrow B` configuration outperforms strong separated, one-way and replay controls.

This module's

```math
G_{\mathrm{gen}}
```

asks whether the **MKUFT generator procedure** outperforms strong scientific/search alternatives.

These are distinct:

```text
human–AI coupling advantage
≠
MKUFT method advantage
```

Either may be positive while the other is null.

Therefore a recording, transcript or provenance chain showing how an insight formed can be scientifically useful for reconstructing the candidate coupling process, but it is not confirmatory superadditivity evidence unless the comparator, task, score and information conditions were fixed prospectively enough for the claimed test.

Likewise, a positive superadditivity result would not by itself validate MKUFT's scientific generator.

## 8. Prospective decomposition test

The simplest direct test of the repeated operation should make the predicted distinction fail-able before the answer is known.

For a fresh task or system not used to construct the operator, freeze:

1. **apparent object** — what the current/native representation treats as one object or equivalence class;
2. **predicted split** — which two or more decision-bearing properties/relations the generator predicts should be separated;
3. **typed addresses** — what the separated objects are, including units/measurement type, scale, state and boundary where material;
4. **carrier/refusal rule** — what relation is predicted to carry a property between them, or why transfer should fail;
5. **target consequence** — what prediction, intervention, classification, recovery or closure decision should change if the split is useful;
6. **strongest native baseline** — what ordinary/domain-native model already predicts;
7. **falsifier/reduction** — what result would show the split is unnecessary, incorrectly typed, already fully native, or non-discriminating;
8. **search budget and stopping rule** — how much branching/revision is allowed before the attempt counts as spent.

Then expose the result.

A successful test requires more than finding language that can describe the answer afterward. The predeclared split must materially improve the target relative to the strongest baseline.

> **Retrospective rhyme earns a candidate. Prospective discrimination earns generator credit.**

## 9. Transfer and independent-use burden

A method can work well for the originating Mark–Kairos development loop without yet being a generally transferable scientific method.

Keep these claims separate:

```text
originating implementation has local merit
≠
procedure transfers to a fresh model/operator
≠
procedure transfers across scientific domains
≠
procedure is historically novel
```

A broad general-method claim should therefore eventually face at least one strong independent-use condition, such as:

- an independent scientist or technical operator applying the public procedure without reconstruction help from the originating pair;
- a fresh model or model family supplied with the same public method and admissible resources;
- blinded or masked task assignment where the expected decomposition is not supplied by the evaluator;
- another domain whose mapping and score are frozen before the answer is inspected.

If only the originating pair obtains the gain, report implementation-local performance and test the coupling separately under Module 24B. Do not silently upgrade it to general method validity.

## 10. Why the compact loop now looks easier than it was to build

The final operational loop is short:

```text
split
→ type
→ test carrier
→ test future consequence
→ preserve / reopen / repair
```

That compactness should not be confused with triviality or with evidence of novelty.

The loop is usable only because substantial supporting machinery is already in place, including:

- exact-object and boundary custody;
- typed address discipline;
- no-untyped-inheritance control;
- equation/unit hygiene;
- strongest-fair-null comparison;
- state/address sufficiency tests;
- prospective/held-out scoring;
- prior-art subtraction;
- local-versus-parent lineage accounting;
- preserve-or-reopen reuse;
- stopping and failure conditions.

Without those controls, `look for a hidden distinction` is just flexible pattern search. It can always produce another story after the answer is known.

The scientific achievement of a mature method, if it survives, is partly that the visible operation becomes simpler while the controls remain underneath it. That engineering fact does not establish that the method works better than alternatives; `G_{\mathrm{gen}}` exists to test exactly that.

## 11. Failure and reduction rules

The broad generator candidate weakens, contracts or fails if any applicable condition holds:

- prospective `G_{\mathrm{gen}}` does not exceed the strongest fair baseline under the declared margin and uncertainty;
- apparent successful distinctions are selected after outcome inspection;
- fresh failures disappear from the Module 29A lineage ledger;
- performance gain is explained by extra time, information, compute, human guidance, model access or revision opportunity;
- native-domain methods already perform the full operation with equal or better discrimination and no residual MKUFT gain remains;
- the cross-module map depends mainly on common descent or repeated authoring vocabulary rather than a parent-changing operational relation;
- the decomposition adds complexity without improving a fresh target;
- different tasks use incompatible scores but are averaged anyway;
- only the originating human–AI pair can reproduce the result and the claim is nevertheless presented as generally transferable;
- the method can reinterpret every failure as another successful discovery opportunity without paying portfolio cost.

Reduction outcomes are legitimate:

```text
no prospective advantage
→ retain useful local discipline if warranted
→ contract broad generator claim

full gain explained by established prior art
→ classify MKUFT contribution as synthesis / translation / implementation

originating pair only
→ retain implementation-local result
→ test coupling separately

mixed task portfolio
→ preserve the vector / bounded task-specific claim
→ do not force a universal score
```

A failed generator benchmark does not retroactively erase a correct mathematical identity, a successful domain-specific experiment, or another independently supported local result.
