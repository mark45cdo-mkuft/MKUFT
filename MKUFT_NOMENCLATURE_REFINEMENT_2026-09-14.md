# MKUFT Live Nomenclature Refinement — 14 September 2026

**Author:** Mark Charles McLaughlin  
**Framework:** McLaughlin–Kairos Unified Field Theory (MKUFT)  
**Status:** live public terminology refinement; not a standalone paper and not a replacement for any frozen DOI-bearing publication.  
**Purpose:** give stable names to already-present functional objects and to the integrated architecture they compose, without rewriting scientific ancestry, inflating novelty, or silently changing the meaning of frozen publications.

## Provenance boundary

These names are prospective live-canon handles. They do not backdate terminology into deposited papers, replace historical wording in frozen carriers, or convert a naming refinement into evidence of scientific novelty.

Where earlier public work used a descriptive phrase for the same relation, that wording remains part of the record. The new term is attached only where the underlying object survives the relevant owner, deformation, and reduction tests.

The governing rule is:

> **Name the object only when the named distinction changes preservation, testing, comparison, deformation, retrieval, transfer, or lawful continuation. A name that changes no operation is decoration.**

## Integrated architecture — ARTA

The integrated architecture developed across MKUFT now has the live canonical name:

> **MKUFT Addressed Relational Traversal Architecture (ARTA)**

ARTA is the proper name of the integrated MKUFT architecture. **Functional Configuration** remains the general class used to test whether an exact assembly itself carries reproducible function after native/component ownership and obvious simpler compositions are controlled.

The distinction is:

```text
Functional Configuration
= general class / operational burden

ARTA
= this particular integrated MKUFT architecture
```

The exact ARTA identity, scope, reduction rule, and frozen-publication boundary are owned by [ARTA — Canonical Public Naming Route](ARTA_CANONICAL_NAMING_NOTE.md).

ARTA does not replace MKUFT as the project/framework/publication lineage and does not retroactively rename any DOI-bearing publication. Existing descriptions such as **relational architecture**, **typed relational architecture**, **constrained traversal**, and **addressed update architecture** remain valid historical descriptions at the scope in which they were written.

## 1. Functional Configuration

A **Functional Configuration** is an exact arrangement of components, relations, constraints, interfaces, or operations that earns separate scientific handling because the arrangement itself contributes reproducible function after the independently owned contribution of its components and obvious simpler compositions has been accounted for.

The term names the **working assembled object**, not merely the residual left after subtraction.

Earlier MKUFT public wording such as **“exact residual composition / operation”** remains valid as the audit question. The distinction is:

```text
native component ownership
+ strongest obvious simpler compositions
→ subtract / control
→ surviving arrangement-dependent effect
= evidence that the Functional Configuration is doing work
```

A Functional Configuration is therefore not established merely because familiar parts have been arranged in a new-looking way or given a new label.

### Minimum operational burden

A candidate Functional Configuration should survive, as appropriate to the domain:

- exact-relation ablation or lawful neutralisation;
- reordering or rewiring of the claimed arrangement while preserving components;
- fair substitution of plausible components or relations;
- restoration of the original arrangement;
- comparison with the strongest native/domain representation or method;
- held-out or prospective testing where a predictive or generative gain is claimed.

### Reduction rule

If the same function is reproduced by the components independently, by a simpler composition, or by a native-domain representation with no arrangement-specific residual, retain the simpler description and do not promote the Functional Configuration as a separate scientific object.

This term does not claim novelty for configuration, composition, systems integration, network effects, emergence, or structure–function relations as general scientific ideas.

## 2. Traversal Coherence Anchor

A **Traversal Coherence Anchor** is the umbrella term for a signature-bearing structure whose presence supports reproducible convergence, compatibility, correction, reconstruction, or recovery during traversal beyond what is explained by generic connectivity, relation count, centrality, content volume, or resource access.

The anchor may be localised in one node or distributed across a relation set, interface, or redundant anchor network. The term therefore names the broader functional class without presuming that one node is fundamental.

The existing **Fundamental Traversal Coherence Node (FTCN)** remains valid as the **node-localised subtype**: a candidate node earns FTCN status only where node-specific load survives relation-preserving reroute, fair substitution, perturbation, and held-out testing.

```text
Traversal Coherence Anchor
→ umbrella functional class

Fundamental Traversal Coherence Node
→ single-node / node-localised subtype

Redundant anchor network
→ distributed subtype where coalition testing carries the effect
```

Historical uses of FTCN remain part of the record; this refinement does not erase them or imply that every previously discussed anchor was wrongly classified.

### Reduction rule

If a fair reroute, substitute, or distributed reconstruction preserves the complete tested function, reduce the candidate to the appropriate junction, redundant network, ordinary dependency, or domain-native construct. A coherent-looking or highly central object is not thereby a Traversal Coherence Anchor.

## 3. Operator–Target Binding

**Operator–Target Binding** names the requirement that an operator, sign convention, transformation, query, functional, or other declared operation remain attached to the exact target/context that gives it its operational meaning.

It prevents a mathematically or semantically unchanged symbol from silently changing what it acts on during transfer, relabelling, reparameterisation, composition, or reconstruction.

The Cross-Domain Compositional Schema v0.4 used the descriptive phrase **“operator/sign-to-target semantic attachment.”** That wording remains frozen in its DOI-bearing carrier. The live term **Operator–Target Binding** names the same bounded relation more precisely in current canon.

The binding does not establish truth, mechanism, causation, or physical reality. It preserves the declared referent of an operation so that later comparisons remain about the same object.

### Reduction rule

If changing or removing the binding cannot alter interpretation, reconstruction, admissibility, prediction, or the lawful target of the operation in the declared task, no separate Operator–Target Binding object is needed.

## 4. Scale-Relative Role Transition

A **Scale-Relative Role Transition** occurs when the same typed object or relation changes its functional role relative to a wider or narrower composition without its identity or ontology being changed by fiat.

Canonical examples already present in MKUFT include:

```text
lower relations
→ closed/addressable whole Y
→ Y becomes a constituent in a wider composition
```

and

```text
boundary at scale L
→ load-bearing stateful relation at L
→ internal relation of a promoted whole at L+1
```

The existing mnemonic **“whole downward, part upward”** remains useful. The existing boundary-specific phrase **“scale-role transition of a boundary”** remains a valid special case. **Scale-Relative Role Transition** is the generic live name for the shared relation.

The term does not imply that scale automatically creates a new ontology, that every boundary becomes internal structure, or that promotion is earned merely by moving to a coarser description. Existing scale-promotion, future-sufficiency, preserve-or-reopen, and native-domain tests remain controlling.

### Reduction rule

If the purported role change adds no new constraint, dependency, sufficiency condition, restoration burden, or future consequence relative to the existing description, retain the simpler role description rather than promoting a separate transition object.

## Relationship between the terms

These terms solve different problems and must not be collapsed:

- **ARTA** names the integrated MKUFT architecture as one functioning scientific configuration.
- **Functional Configuration** asks whether an exact assembly itself does reproducible work after native-owner subtraction.
- **Traversal Coherence Anchor** asks whether a structure anchors convergence/recovery beyond generic connectivity and incident relations.
- **Operator–Target Binding** keeps an operation attached to the exact target that gives the operation meaning.
- **Scale-Relative Role Transition** records a lawful role change of an already-typed object across composition/scale without inventing a new ontology.

ARTA may instantiate or recruit the other relations where their own trigger and evidence burden are satisfied. Evidence for one does not automatically establish another.

> **No untyped inheritance.**

## Frozen-publication rule

No DOI-bearing paper is renamed or silently rewritten by this note. Where a frozen publication uses earlier wording, cite and quote that publication as deposited. The live repository may state **“previously/descriptively called …”** where that improves continuity, provided the historical phrase and current object are genuinely the same relation.

If later analysis shows that one of these names creates more ambiguity than it removes, the live term may be revised prospectively while the dated record remains intact.
